# Memory replay first version

Open Memory → Life Memory timeline → a saved event → Open memory replay. The replay shows swipeable source cards for the event/date, recorded people, recorded place, exact saved notes and supporting source. Previous/Next controls duplicate swipe navigation. Read this card uses the existing voice service to narrate the current card, including whether attendance is confirmed or merely planned. No text model invents a recap. Missing people/place/notes omit those cards rather than filling gaps.

The view explicitly labels itself as a saved-memory recap, not a recording or footage. This first version has no generated scenery, photos, video, facial identification, photo-library access or exported movie. It is the factual card-and-narration foundation for the discussed cinematic experience. Media attachments or clearly labelled illustrations can be separate later work. Existing event editing corrects the source data; the replay reopens the saved version. Narration can send saved text to Max/OpenAI through the existing voice path and may use iPhone speech fallback, as disclosed in the view.

The replay menu can hide/show people, place and notes cards. This is a presentation preference, not deletion: the stored fields and the supporting source remain available. Date/attendance and source cards cannot be hidden. Forget event requires confirmation and removes the event from future memory retrieval; original calendar entries and chat history remain separate. Account scope is checked before loading and modifying events. Account changes, leaving the replay, moving between cards or backgrounding stop narration. Foregrounding reloads the saved event so forgotten content is not recreated. Memory pause disables narration and new preference writes while retaining inspection/forget controls.

Added native tests cover exact saved text, missing details, planned/confirmed status, mandatory evidence despite hidden preferences and decoding older events. Existing backend tests remain applicable because no backend route is added. Native builds/tests require this PR's own CI. Physical acceptance remains NOT RUN: check small-screen/large-text navigation, VoiceOver, reading/stopping a card, card changes during speech, background/sign-out cleanup, hidden-card persistence, edits and forgetting. Real iPhone UI, voice playback and signed TestFlight delivery are unverified. No deployment or merge is performed here.
