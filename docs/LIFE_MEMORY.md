# Life Memory first slice

Memory → Life Memory timeline connects a person, place, event date, discussion notes, attendance state and supporting source snapshot. Users can add/review events, correct them, search by keywords and forget them. AI tools can propose an editable event review after an explicit save request and recall saved events with their actual source labels, excerpts and dates. Nothing is saved by a proposal alone. Attendance starts unconfirmed and changes only through user review; a future event cannot be marked attended.

The calendar review action requests EventKit access explicitly and loads up to 50 timed entries from the past six months. These are candidates, not saved memories or evidence of attendance. Selecting one opens the editor; only Save persists its snapshot. People are taken from the entry's attendee names, which can be incomplete or include invitees who did not attend. The user must correct and confirm those details. This version does not silently import calendar history, monitor location, identify faces, read contacts, or connect email. Manually entered notes are supported; existing chat/note archives are not automatically indexed.

The local recall tool supports keywords and an inclusive/exclusive date range, returns at most 20 results and the full match count, and retains multiple plausible matches. The backend instructs the model to cite the saved source and date, clarify ambiguity, distinguish planned from confirmed meetings and state insufficient evidence when nothing matches. Source-backed answer quality is not established by a passing build. Retrieval is lexical, not semantic vector search; paraphrases can miss entries. Model answers remain subject to live acceptance testing. The timeline displays source snapshots directly so users can inspect them.

Data is account-local and not synced. Memory pause prevents model recall and new event writes; existing events can still be inspected or forgotten. Deleted events cannot be resurrected by an old editor. Forget removes future memory retrieval; chat history, original calendar entries and previously issued answers are separate. Cancel, conversation stop, background cleanup and account changes invalidate outstanding proposals. Calendar snapshots do not update automatically when the original event changes. Storage allows at most 1,000 events and reports failure without silently dropping old events.

Validation: existing 57 backend tests pass locally. Native tests cover recall with source/attendance evidence, ambiguity preservation, accent-insensitive keywords, date boundaries, correction/deletion, memory pause, account isolation and proposal cancellation. Native build and tests need this PR's own CI. Backend deployment is required for the new tool allowlist and instructions; the native build alone does not deploy it.

Physical acceptance (NOT RUN): save a meeting through a real spoken request, confirm its date/person/place and attendance, then ask about it using incomplete details and verify the correct person and actual supporting source/date. Add a second plausible meeting and require a clarifying question. Import a past calendar candidate without confirming attendance and verify no answer claims attendance. Correct and forget it, then verify later searches use the correction and no longer retrieve the forgotten event. Repeat with memory paused, cancelled review, sign-out and account switching. Test real calendar denial and empty results separately. Signed delivery, real provider answer accuracy and physical-device behavior remain unverified.
