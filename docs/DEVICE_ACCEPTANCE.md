Baseline reviewed: [PR #3](https://github.com/GindausD2/GindausD/pull/3), open and draft, head `f1bb198d9e751e03e9c99fd602cfb535d6ea6fee`. [Run 40702378486](https://github.com/GindausD2/GindausD/actions/runs/40702378486) completed successfully for that head. Its job steps confirm simulator app/extensions, unsigned iPhone SDK build, packaged-app checks, native simulator regression tests, web type checking, backend tests, Deno checks/transport fixtures and disposable PostgreSQL quota tests. None proves signed delivery or physical-device behavior.

All rows below are **NOT RUN**. Record PASS, FAIL or BLOCKED separately for each device/build and scenario. A missing prerequisite is BLOCKED, never PASS. Keep screenshots/recordings and redacted request status evidence with each result. No device support or TestFlight delivery has been verified by this review.

Before execution: obtain a signed build tied to the tested commit, install it through the intended TestFlight path, and record app version/build, commit, iPhone model, iOS version, backend environment and tester/date. Confirm its app and extension signing/entitlements. Use a Dynamic Island iPhone and a supported physical iPhone without Dynamic Island for the Lock Screen fallback. Use staging accounts for an unexpired guest, expired guest, subscribed account, and account without a subscription. Do not use an unsigned CI artifact as installation evidence.

| Check | Execute | PASS criteria | FAIL criteria |
| --- | --- | --- | --- |
| Login and access | From signed out, complete real Apple login; separately cancel it and retry. Test permanent accounts with/without a verified subscription. Relaunch. | Successful login restores the correct account. Home appears only for valid guest or subscribed access. Cancel/error stays recoverable at the access gate. Session restoration retains the same account and entitlement gate. | Login hangs/crashes; wrong identity; cancellation grants access; unsubscribed account reaches Home or managed AI. |
| Demo access | Select Try Demo without Apple login or payment; use a real managed request; terminate/relaunch. | A distinct anonymous guest reaches Home, receives an actual backend response and displays remaining trial time. Relaunch resumes the same guest and original expiry. | Demo requires Apple/payment, stays blocked, only shows a fixture reply, changes guest on ordinary relaunch, or restarts the trial clock. |
| Shortcut discovery | Open Your space → Dynamic Island → Apple's Shortcuts page. | Both **Start Max Island** and **Activate Max** appear in the real Shortcuts app and can be added/run. | Missing/incorrect action; setup only opens a mock preview or dead link. |
| Start Max Island | Run from Shortcuts with Max terminated, foregrounded and backgrounded; repeat after login and demo access. Start with microphone permission undetermined. | Max opens; access/foreground activation completes first; one Live Activity starts or resumes. No microphone permission request, microphone capture or listening indicator. | Any microphone capture/prompt, access bypass, duplicate activities, lost cold launch or repeated execution of one request. |
| Activate Max | Repeat the same cold/warm/background launch matrix for both guest and subscribed accounts. | Max opens, completes the access gate, then requests needed microphone/speech permission and starts one foreground voice capture. One request executes once. | Capture before access/foreground, missing activation, duplicate capture, background listening or execution again on the next foreground. |
| Pending requests | Invoke each shortcut while signed out; finish initial login/demo within five minutes. Repeat but leave the request abandoned for more than five minutes before completing access. | Fresh request survives initial sign-in/session restoration and executes once after Home is allowed. An abandoned request older than five minutes does not execute. | Request bypasses the gate, is lost during timely initial login, executes more than once, or executes after expiry. |
| Microphone permissions | On a fresh permission state, allow capture. Separately deny microphone, deny speech recognition, then grant each in Settings and retry. Finish/cancel capture; lock/background the app. | Allowed capture produces spoken words. Denial explains how to recover and leaves typing usable without recording. Retry works after Settings. Finish/cancel/background stops actual capture; no delayed permission callback reopens it. | Recording while denied, crash/stuck listening, missing recovery, or continued/restarted background capture. |
| Live Activity lifecycle | Repeat Start Max Island during an active session; finish a conversation. Dismiss/end the activity, then run again. Test with Live Activities disabled. | Repeated runs leave one Max activity and preserve its current conversation phase. Conversation completion returns to idle. Ended/dismissed activity is not reused; a later explicit run creates a fresh activity. Disabled state shows “Allow Live Activities for Max in iPhone settings, then run Start Max Island again.” A start failure shows a useful retry message. | Duplicates, phase reset on resume, stale dismissed session/snippet, silent disabled failure or false claim that the activity started. |
| Island and Lock Screen | On Island hardware inspect compact/minimal/expanded presentation and the Lock Screen; repeat Lock Screen checks on hardware without Island. Include large text. | Max branding/status remain legible and unclipped in the relevant presentations. Real phases follow foreground activity and return to idle. Non-Island device shows its Lock Screen activity. System dismissal/expiry is respected; relaunch/restart recovers safely. | Missing supported presentation, clipping/overlap, stale listening/speaking, or behavior depending on an unlimited/permanent overlay. Do not impose a guaranteed activity lifetime: iOS controls it. |
| Talk / Briefing / Plan | Use each real Live Activity link from the Lock Screen/expanded activity with Max cold and warm; repeat while access is gated. | After required unlock/access, Talk opens voice, Briefing opens the briefing flow, and Plan opens the next-hour planning flow. Correct action runs once, with no gated access bypass. | Wrong action, dropped cold link, duplicate action, stale account data, or capture/action before access. |
| Sign-out and account switch | Start capture/playback and an activity; queue a shortcut; sign out. Sign into another account and run a new shortcut. | Capture/playback stop, the old activity disappears, queued old requests are cleared, and the next account reveals no prior messages/snippets. A fresh shortcut still works through the new account's access gate. | Old audio/activity persists, a queued request executes in the next account, or prior account data appears. |
| Demo expiry | Use a staging guest whose verified creation time reaches `created_at + 604800 seconds`. Test while open, on foreground, via both shortcuts and an activity link. Refresh the token/relaunch the same guest. | At/after expiry, backend returns **402 / demo_expired** before quota/provider work. The open UI reaches continuation within its 30-second refresh, foreground rechecks expiry, and capture/playback/activity stop. Shortcuts/links cannot reopen usable Home or AI. Same guest retains the original expiry. | Any post-expiry managed response, microphone/activity access through a shortcut, trial reset on refresh/relaunch, or failure to close expired access. |
